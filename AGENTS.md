# Project working rules
- Build an accessibility practice workspace for product teams. Use a confident high-contrast, chartreuse and charcoal visual system.
- Start every session by reading this file, BACKLOG.md and Git status. Review the previous implementation and diff, then debug open issues.
- Each day includes code review, relevant tests, today's feature, documentation/backlog updates, debugging and a final regression pass. Run tests/typecheck/build when dependencies are installed.
- Never describe a sample checklist as proof of conformance. Explain limits and keep manual, assistive-technology and lived-experience review in the workflow.
- Keep all controls keyboard accessible, labels explicit, zoom usable and status understandable without color. Support both themes and responsive layouts.
- Use React, TypeScript, Vite, Material UI and React Icons. Prefer semantic HTML and tested MUI primitives.
- Update BACKLOG.md daily, record newly found work and prepare tomorrow's scope.
- Keep .npmrc ignored and local. Do not commit user audit evidence, credentials, .env or build output. Never rewrite history.
- Limit changes to this repository and make meaningful commits after checks pass.
